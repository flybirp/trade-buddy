# 研究数据流水线

## 目标

把用户的一句买入意图转成截至决策时点的事实快照。先拿事实，再做判断；不向用户索要能自行获取的信息。

## 最小输入

- 标的名称或代码
- 计划买入日期
- 计划价格或价格区间
- 持有期限
- 目标收益率

缺少标的代码、当前价格或交易日期时自动补齐。缺少持有期限或目标收益率时只追问对应项。

## 数据分层

### A. 标的与行情

使用 WeStock Data：

- `search`：名称转标准代码
- `kline --period day --limit 60`：日线、量价、振幅、关键位
- `kline --period week --limit 52`：中期趋势
- `minute --days 5`：需要判断盘中结构时调用
- `technical --group ma,macd,rsi,boll`：辅助指标
- `chip`：筹码成本，仅作为辅助

注意：当前渠道 `quote` 不可用；盘后用最新日K收盘价，必须标明“最近收盘”，不能称为实时价。

### B. 公司基本面

使用 WeStock Data：

- `profile`
- `finance --num 8`：至少覆盖利润、资产负债、现金流；季度与年度口径分开
- `shareholder`
- `dividend --years 5`
- `reserve`

### C. 一手公告

主源 `cninfo-stock-data`：

- `query <code> --since ... --until ... --json`
- `reports <code> --json`
- 深市需要调研记录时用 `research <code> --json`

兜底 `cninfo-filing-scraper`：

- 用于按公告类型过滤、核对遗漏和下载原文
- 必须在受控输出目录运行，因为 `search` 会生成 JSON 文件

重点主动检索：业绩快报/预告、减持、解禁、回购、并购重组、重大合同、风险提示、问询/监管、诉讼、质押。

### D. 新闻、行业、同业与市场环境

- 腾讯新闻：近期公司、行业、政策新闻；按其当前 help 调用
- `wb-finance-skill + agentic_search`：行业景气、产业链位置、同业候选、市场环境、反向证据
- WeStock Data：指数/板块K线、热门板块、板块成分股与资金

通用检索不是实时行情库。炸板率、连板高度、隔日溢价等字段缺失时必须注明，并降低短线判断置信度。

### E. 用户边际信息专项检索

用户提出常规数据源未覆盖的低估点或催化点时，停止使用通用关键词做宽泛搜索，改为围绕用户命题拆出实体、动作、传导关系和时间窗，进行定向检索：

- 同义词、旧称、子公司、参股公司、产品名、客户/供应商名
- 公告、互动问答、调研纪要、监管文件、招投标、产品页等一手或近一手证据
- 能证实传导链的业务占比、持股比例、订单金额、价格、产能和财务代理变量
- 能推翻用户观点的反向关键词和替代解释

用户提供的截图、链接、文档或口述属于“待核验线索”。保存其原意，但只有在来源与内容验证后才能升格为事实。若确实无法公开验证，列出下一可观察事件，而不是强行给真伪结论。

### F. 条件辅助

量能异动监控只在涉及低位放量或横盘缩量时调用。只采用量比、振幅、价格分位、均线距离等原始计算；“吸筹”“洗盘结束”视为待验证假设。

## 来源优先级

1. 交易所/巨潮公告、公司定期报告
2. 结构化行情与财务接口
3. 券商研报
4. 权威财经媒体
5. 社区观点，仅作情绪样本

冲突时保留差异，优先一手来源，不静默选择。

## 时间与口径

每条关键事实记录：

```json
{
  "source": "来源",
  "as_of": "查询或披露时点",
  "period": "报告期/行情日期",
  "url": "原文链接",
  "type": "raw或derived",
  "confidence": "high/medium/low"
}
```

- 行情按交易日；公告按披露时间；财报区分报告期和公告日
- 不用未来数据解释过去决策
- 价格、复权、同比/环比、净利润/归母净利润必须统一口径

## 交付约束

事实快照只保留影响决策的内容：

- 3–6条关键事实
- 2–3条反向证据
- 数据缺口
- Reference 列表

禁止数据堆砌，禁止由K线倒推未证实的主力行为。
